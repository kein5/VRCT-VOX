# VRCT-TTSの公開と上流への提案

2026-10-28のユーザー指示: 開発を継続し、リポジトリ名をVRCT.cppから**VRCT-TTS**へ変更する。
予定機能が完成した後に成果を公開し、上流へ全部または一部の取り込みを打診する。

GitHub上の`kein5/VRCT.cpp`を[kein5/VRCT-TTS](https://github.com/kein5/VRCT-TTS)へ改名した。
repository IDは1435087352のまま、fork元は[misyaguziya/VRCT](https://github.com/misyaguziya/VRCT)、default branchはdevelop。
改名前から公開リポジトリだったため、これは公開設定の変更ではない。
ローカルのoriginを新URLへ更新し、fork元をupstreamに登録した。worktreeのディレクトリと履歴は維持する。
GitHub連携には改名機能がなかったため、同じ所有者の認証を確認したghからnameだけを変更した。

## 開発中の扱い

現在の音声機能はローカルのレビュー可能なコミットで保持する。改名時点ではpush・release・上流への連絡はしていない。
既存の`VRCT`内部識別子、設定形式、IPC/OSC契約をリポジトリ改名だけで一括置換しない。
配布アプリ名とfork固有identifierはP5でインストール先・設定移行・既存VRCTとの共存を確認して揃える。
提供された仕様原本のファイル名や過去の検証記録は原本・履歴として残す。

## 完成後に行うこと

1. [完了記録](completion-ledger.md)のP1〜P5を実装と実測で閉じる。未検証をPASSへ読み替えず、
   既存機能との互換性・停止/切断・両OS・混在負荷・ライセンスを確認する。
2. fork専用の説明、設定手順、測定条件、既知の制約、変更履歴を整えて成果を公開する。
   独自配布物に制限付きOCRモデルや無断のVC/TTS/ASR重みを含めない。配布対象ごとに依存・許諾を確認する。
3. 上流の当時のCONTRIBUTING、issue/PR方針と現行コードとの差分を確認し、短い導入提案を送る。
   全部を一括採用してもらう前提にせず、保守負担と独立して取り込める単位を提示する。
4. 取り込み対象が決まったら、その範囲に絞ったPRへ整理する。上流へのmergeや破壊的な履歴変更はこの依頼には含めない。

取り込み候補は、Linux起動互換、音声イベントとTTS、仮想マイクと保持ミュート、外部VC、ASR、翻訳発声、
試験・計測ツールなどを分けて説明できる形で保持する。fork固有の表示や配布設定は機能変更と分離する。
本文や性能値は完成時点の実装・測定結果で作り直す。現段階で上流へ送る提案文を完成済みとは扱わない。

この指示は従来の「未依頼の公開・upstream連絡なし」を、**予定機能完成後の公開・打診に限って更新**する。
完成条件に達する前にメッセージを送らない。
