# Windowsで未確認の変更 — 2026-11-13

0.1.0-beta.6（2026-11-12、`efa73156`）のあとに`develop`へ入った変更のうち、Windowsの実機で確かめていないものの一覧です。開発と検証は、2026-11-13にLinuxのPCからWindowsのPCへ移りました。

確かめた行は、この一覧から消してください。結果は、[Windows音声の検証記録](windows-voice-report.md)か、該当する仕様に書きます。実機試験の手順は[Windowsの実機試験](windows-field-tests.md)にあります。

## 確かめてある範囲

- この期間の変更は、CachyOS（KDE Plasma、Wayland）のPCで、実際のアプリを動かして画面ごとに確かめました。
- Windowsでは、CIの`backend-windows`と`headless (windows-latest)`が通っています。どちらもPythonの試験です。画面、WebView2での描画、実物のVRChat、キーの入力は含みません。
- この期間の変更を入れたWindowsのインストーラーは、まだ作っていません。

## Windowsで確かめること

上の行ほど、Windowsで動きが変わる見込みが高いものです。

| 変更 | 確かめること | Windowsで動きが変わりうる理由 |
|---|---|---|
| 読み上げと声のホットキー（#218） | 「設定」→「ホットキー」の「読み上げと声」で、停止、ミュート、TTS、RVCの4件にキーを割り当てる。メイン画面を前にしたときと、ほかのアプリを前にしたときに押し、画面のボタンと同じに動くことを見る。設定を開いている間は効かないことも見る。 | Linuxで実際にキーを押して確かめたのは、X11（XWayland）のウィンドウとして動かしたときだけ。Windowsは同じプラグインで登録するが、OSの登録の仕組みが違う。 |
| VRChatの検出（#221） | VRChatを起動する前、OSCを有効にして起動したあと、終了したあとのそれぞれで、「設定」→「VRChat」の先頭の表示を見る。メイン画面の「クイック設定」にも同じ表示が出る。 | このPCの中の探索（mDNS）と、ループバックのHTTPを使う。ファイアウォールやネットワークの構成が探索を止めると、VRChatが動いていても「検出できません」と出る。表示は案内だけで、送信は止めない。 |
| 翻訳モデルの取得（#213） | モデルがない状態で、メイン画面の「翻訳」を初めてオンにする。確認の画面が開き、同意して取得が終わると翻訳がオンになることを見る。会話が空の画面の「使う前の準備」からも、同じ画面が開くことを見る。 | インストーラーで入れたアプリでの保存先と、WebView2での確認画面の表示を見ていない。 |
| メイン画面の上の帯とサイドバー（#216、#217、#222） | 停止とミュートのボタン、「クイック設定」のメニュー、ウィンドウの幅を狭めたときの表示、サイドバーを畳んだときの言語の表示を見る。 | WebView2とWebKitGTKでは、描画と日本語のフォントの幅が違う。 |
| 設定のページの構成（#219、#220、#223） | 「チャット読み取り」のページ、翻訳の接続先の折りたたみ、音声認識の「区切りと待機の調整」と「認識のしきい値」、保存の帯の「保存すると適用」を見る。設定の検索から、折りたたんだ項目へ移れることも見る。 | Windowsだけに出る項目がある（チャット読み取りの、ヘッドセットの映像の読み取り範囲など）。新しいページの構成では見ていない。 |
| beta.6の直後の画面の修正（#203、#205、#206、#208、#210） | お知らせがスイッチや入力欄に重ならないこと、起動時の警告が該当するときだけ出ること、ミュート同期が使えない理由が表示の言語で出ること、設定を閉じてもASRのサーバーが止まったままであることを見る。 | Linuxでだけ確かめた。 |
| VRChatに送らなかったメッセージの表示（#215） | 「VRChatにメッセージを送信する」をオフにして送り、ログに「VRChatには未送信（設定でオフ）」と出ることを見る。 | OSによる違いはない見込み。経路はCIのPythonの試験で通っている。 |

LinuxのPCで測った参考の値です。VRChatの検出は、VRChatを起動してから6〜8秒で「検出しました」に、終了してから3〜4秒で「検出できません」に変わりました（各2回）。Windowsでの値は測っていません。

## Windowsでは確かめなくてよい変更

次の変更は、Linuxの実機試験の道具だけを変えています。PipeWire、KDE、XWaylandを前提にしていて、Windowsでは動きません。

- #202、#204、#207、#209: Linuxのネイティブ試験とAppImageの試験
- #211、#212、#214: `tools/native_acceptance.py`と`tools/vrchat_voice_host.py`（実物のモデルとVRChatを使う受け入れ試験）

## どちらのOSでも確かめていないこと

- 韓国語と中国語の表示。この期間に足した文言は、英語で出る。
- スクリーンリーダーでの読み上げ。
- 実際のキーを入れたクラウドの音声認識。#223で接続先を折りたたんだ表示は、キーがない状態で見た。
- 音声認識のページの「リアルタイム字幕」の欄は、折りたたんでいない。ページの中でいちばん長い欄として残っている。

Linuxで残っている未確認（実物のヘッドセット、KDE以外のデスクトップなど）は、[README](/README.md)の制限の節に書いてあります。
