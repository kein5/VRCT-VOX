# 仕様書：RVC 推論ランタイム再実装

- 対象: 声変換（VC）推論ランタイムの新規実装
- 方針: 既存実装のコードを移植・複写せず、処理仕様を読み解いて再実装する
- 状態: 仕様ドラフト（未決事項は 15 節）
- 日付: 2026-11-15
- 参照元: RVC-Project / Retrieval-based-Voice-Conversion-WebUI（現行 main）の公開仕様・挙動

## 1. 目的と範囲

### 1.1 目的

外部ランタイムとして取得・起動している RVC を、アプリ同梱の推論専用ランタイムとして
再実装する。既存の声モデル（`.pth`）とインデックス（`.index`）がそのまま使え、
本家実装と perceptually 等価な変換結果が得られることを成立条件とする。

### 1.2 対象に含むもの

- 推論（ファイル／ストリーミング両方式）
- モデル形式 v1 / v2、F0 あり（NSF 版）/ F0 なし（nono 版）
- 出力サンプルレート 32k / 40k / 48k のモデル
- F0 抽出は RMVPE を必須とし、抽出器は差し替え可能なモジュール境界として定義する

### 1.3 対象に含まないもの

- 学習（データセット作成、特徴抽出、学習、インデックス構築）
- WebUI / Gradio 系の UI
- 音源分離（UVR / PyMSS 等）、モデルマージ等の周辺ツール
- Seed-VC（廃止決定済み）

## 2. 全体パイプライン

```
入力音声（任意のサンプルレート、モノラル化）
  → 16kHz 化
  → ハイパスフィルタ（5次 Butterworth、48Hz、filtfilt＝ゼロ位相）
  → F0 抽出（RMVPE、100fps）→ 補間 → キー変更 → mel 量子化（coarse 1..255）
  → HuBERT 特徴抽出（50fps、v1: 256次元 / v2: 768次元）
  → インデックス検索ブレンド（index_rate、protect）
  → 特徴を ×2 アップサンプル（100fps 化）
  → 合成器（VITS + NSF）→ 目標サンプルレートの波形
  → RMS ミックス（任意）→ 出力サンプルレートへリサンプル（任意）→ ピーク正規化
```

フレームの基本単位は 16kHz で 160 サンプル（10ms）＝ 100fps。以後の各段はこの
フレームレートを基準に記述する。

## 3. モデルファイル仕様

### 3.1 声モデル（`.pth`）

PyTorch チェックポイント形式の辞書。推論に必要なキーは次のとおり。

| キー | 内容 |
|---|---|
| `weight` | 合成器の state_dict |
| `config` | 構造パラメータの配列（3.2）。末尾が目標サンプルレート |
| `f0` | 1 = F0 あり（NSF 版）、0 = F0 なし。欠落時は 1 |
| `version` | `"v1"` / `"v2"`。欠落時は `"v1"` |

読み込み時の処理：話者数 `n_spk` は `config` の後ろから3番目の要素ではなく
`weight["emb_g.weight"]` の形状（行数）から決め、`config` 側の値を上書きする
（本家の読み込み手順どおり）。

### 3.2 `config` 配列の要素順

合成器コンストラクタの引数順に一致する。

```
spec_channels, segment_size, inter_channels, hidden_channels,
filter_channels, n_heads, n_layers, kernel_size, p_dropout,
resblock（"1" 等の文字列）, resblock_kernel_sizes, resblock_dilation_sizes,
upsample_rates, upsample_initial_channel, upsample_kernel_sizes,
spk_embed_dim, gin_channels, sr
```

参考：v2 / 40kHz の典型値。

```
[1025, 32, 192, 192, 768, 2, 6, 3, 0, "1",
 [3, 7, 11], [[1, 3, 5], [1, 3, 5], [1, 3, 5]],
 [10, 10, 2, 2], 512, [16, 16, 4, 4], 109, 256, 40000]
```

推論で実効的に効くのは、次元系（inter / hidden / filter / gin）、
`upsample_rates`（積が `sr / 100` に一致する。例：40k なら 10×10×2×2 = 400）、
話者埋め込み次元、`sr` である。`spec_channels` は推論経路では未使用（学習時の
スペクトログラム用）だが、構造の同定のため保持する。

### 3.3 インデックス（`.index`）と特徴配列

- FAISS インデックスファイル。学習時に構築された特徴ベクトル群に対する近傍検索用。
- 推論ではインデックスから全ベクトルを復元した配列（`reconstruct_n(0, ntotal)`、
  以下「特徴配列」）を併せて保持する。
- 再実装側は FAISS 形式の読み込みを自前で実装するか、読み込み時に自前形式へ
  変換してよい（7 節の検索意味論を満たすこと）。学習時に作られる `trained_*.index`
  は特徴配列を含まないため使用不可で、`added_*.index` のみが有効——という本家の
  制約を、読み込み時の検証として再現する。

### 3.4 同梱する学習済み重み（データ資産）

コードではなくデータとして同梱する。再実装の対象はこれらを実行する側の構造である。

| 資産 | 役割 | 規模の目安 |
|---|---|---|
| `hubert_base`（Transformers 形式一式） | 特徴抽出（ContentVec 系チェックポイント） | 約190MB |
| `rmvpe.pt` | F0 抽出 | 約181MB |

出所とライセンスは同梱前に個別確認する（14 節）。

## 4. 前処理

- 入力は 16kHz モノラル float 波形に変換する（ステレオはチャンネル平均）。
- ハイパスフィルタ：5次 Butterworth、遮断 48Hz、サンプルレート 16kHz、
  `filtfilt` による前方・後方適用（位相歪みなし）。ファイル方式・ストリーミング
  方式の双方で適用する（ストリーミングでは近似方法を 12 節で定義する）。
- ファイル方式の分割処理：長尺音声は無音に近い点を探して分割し、文脈として
  前後にパディング（reflect）を付けて処理する。本家の参考値（高性能 GPU 向け）：
  `x_pad = 3` 秒（前後パディング）、`x_query = 10` 秒（分割点の探索範囲）、
  `x_center = 60` 秒（分割間隔）、`x_max = 65` 秒（分割なし上限）。
  再実装では同等の意味論を保ち、値は設定可能とする。

## 5. F0 抽出と量子化

### 5.1 RMVPE

- 入力：16kHz 波形。メルスペクトログラム（128 mel、FFT 1024、hop 160＝100fps）を
  U-Net 系エンコーダ＋ BiGRU で処理し、360 ビンの salience（確率分布）を得る。
- デコード（`to_local_average_cents`）：フレームごとに argmax を中心に ±4 ビンの
  局所加重平均で cents を求める。最大確率がしきい値 `thred = 0.03` 未満のフレームは
  無声（cents 0）とする。
- Hz 変換：`f0 = 10 × 2^(cents / 1200)`。変換結果が 10（＝cents 0）のフレームは
  f0 = 0（無声）とする。

### 5.2 後処理と量子化（本家の手順をそのまま仕様とする）

1. 無声フレーム（f0 = 0）を、有声フレーム間の線形補間で埋める
   （全体が無声の場合は補間できず 0 のまま）。
2. キー変更：`f0 *= 2^(transpose / 12)`。
3. 補間後の連続 F0 を `pitchf`（float）として保持する。
4. mel 量子化：`f0_mel = 1127 × ln(1 + f0 / 700)`。F0 の有効範囲は 50〜1100Hz。
   `coarse = round((f0_mel − mel_min) × 254 / (mel_max − mel_min) + 1)` を
   1..255 にクランプしたものを `pitch`（整数）とする。`f0_mel ≤ 1` の位置は 1。

注意：本家現行実装では、`pitchf` は補間後の値であり無声 0 を含まない。
7 節の protect はこの `pitchf` を参照するため、無声区間の検出は実質的に
「全体無声」の場合に限られる。再実装では本家の挙動を忠実に再現し、
「改善」を加えない（差異が出た場合は 13 節の検証で検出されるべきものとする）。

## 6. 特徴抽出（HuBERT）

- 入力：16kHz 波形（チェックポイントの feature extractor 設定に従い正規化する。
  正規化の有無は同梱チェックポイントの設定値が正）。
- 出力フレームレートは 50fps（hop 320）。
- v1：エンコーダ第9層の出力に `final_proj`（768→256 の線形層）を適用した
  256次元特徴。
- v2：エンコーダ最終層（第12層）の出力そのもの（768次元）。
- パディングマスクは通常全 False（無効）として扱う。

## 7. インデックス検索ブレンドと protect

特徴は 50fps の段階で次を行う。

1. 検索ブレンド（インデックスがあり `index_rate ≠ 0` の場合のみ）：
   - 各フレームについて特徴配列から近傍 k = 8 を検索する。
   - 重みは距離の逆数の2乗 `w = (1 / d)^2` をフレーム内で正規化したもの。
   - `特徴 = index_rate × Σ(w_i × 近傍_i) + (1 − index_rate) × 元の特徴`。
2. protect 用に、検索ブレンド**前**の特徴のコピーを保持する。
3. ×2 アップサンプル（8 節）後、protect 適用（`protect < 0.5` かつ F0 ありの場合）：
   - 係数 `pitchff` を、`pitchf > 0` のフレームは 1、`pitchf < 1` のフレームは
     `protect` とする。
   - `特徴 = pitchff × 特徴 + (1 − pitchff) × ブレンド前の特徴`。

## 8. フレームレート変換

- HuBERT 特徴（50fps）を線形補間ではなく nearest で ×2 し、100fps にする
  （PyTorch `F.interpolate(scale_factor=2)` の既定モード相当＝各フレームの複製）。
- フレーム数 `p_len = 入力サンプル数 // 160` とし、特徴が長い場合は `p_len` に切り詰める。

## 9. 合成器

### 9.1 構造

VITS 系ジェネレータ＋ NSF（Neural Source Filter）。

- `emb_g`：話者埋め込み（`sid` → `gin_channels` 次元）。
- `enc_p`（TextEncoder）：特徴（256 / 768 次元）＋ F0 の coarse 埋め込みから
  事前分布の平均 `m_p` と分散 `logs_p` を出す。F0 なし版では F0 入力を持たない。
- `flow`：正規化フロー（逆向きに適用）。
- `dec`（GeneratorNSF）：`z` と連続 F0（`pitchf`）から波形を生成する。
  励起信号は SineGen（F0 に基づく正弦波＋ノイズの混合、アップサンプル過程で
  ソース特徴として注入）。アップサンプルの各率は `upsample_rates` に従い、
  積が `sr / 100` に一致する。

### 9.2 推論手順（F0 あり）

```
g = emb_g(sid)
m_p, logs_p, x_mask = enc_p(特徴, pitch, p_len)
z_p = (m_p + exp(logs_p) × randn × 0.66666) × x_mask
z = flow(z_p, reverse=True, g)
波形 = dec(z × x_mask, pitchf, g)
```

- `randn` による確率的要素を含むため、出力はビット一致しない。
  再実装ではテスト用に乱数シードを固定できるモードを必須とする（13 節）。
- F0 なし版は `enc_p(特徴, p_len)` → 同様に flow → `dec(z, g)`（励起なし）。

### 9.3 ストリーミング用インターフェース

合成器は「左文脈つき窓処理」をサポートすること：

- 入力窓のうち先頭 `skip_head` フレームを文脈として消費し、
  続く `return_length` フレーム分のみを出力する。
- このとき `enc_p` の文脈開始位置は `flow_head = max(skip_head − 24, 0)` とし、
  フローの出力と F0 を対応分だけずらして切り出す（本家の `infer` の
  `skip_head / return_length` 引数の意味論）。

## 10. 後処理

- RMS ミックス（`rms_mix_rate ≠ 1` の場合）：入力音声と出力音声それぞれの
  RMS 包絡（0.5 秒窓、0.5 秒 hop、線形補間でサンプル単位に展開）を用い、
  `出力 *= rms_入力^(1−rate) × rms_出力^(rate−1)` とする
  （`rms_出力` は下限 1e-6 でクランプ）。
- リサンプル（任意）：目標サンプルレート ≠ `resample_sr` ≥ 16kHz の場合のみ。
- ピーク正規化：`|max| / 0.99 > 1` の場合にのみ `32768 / (|max| / 0.99)` を
  16bit 換算のゲインとして適用する。本家のファイル出力は int16 化までを含むが、
  アプリ内パイプラインへ渡す場合は float のままこのゲイン適用まででよい。

## 11. パラメータ対応表（本家 UI との対応）

| パラメータ | 意味 | 既定・範囲 |
|---|---|---|
| `transpose`（f0_up_key） | 半音単位のキー変更 | 0、整数 |
| `index_rate` | 検索ブレンドの混合率 | 0.75（本家 UI 既定）、0..1 |
| `protect` | 無声・息成分の保持率 | 0.33（本家 UI 既定）、0..0.5（0.5 で無効） |
| `rms_mix_rate` | 入力音量への追従率 | 1 で無効（そのまま）、0..1 |
| `resample_sr` | 出力リサンプル先 | 0 = なし |
| `f0_method` | F0 抽出器の選択 | 初版は `rmvpe` 固定 |

本家旧版にあった `filter_radius`（F0 のメディアン平滑）は現行本家の推論経路に
存在しないため、本仕様の対象外とする。

## 12. ストリーミング方式の要件

本家のリアルタイム実装（`rtrvc` / realtime GUI）の方式を要件として整理する。

- 処理単位：入力ブロック（デバイスサンプルレート換算で可変、16kHz 換算
  `block_frame_16k`）ごとに推論する。
- F0 抽出窓：ブロック長 ＋ 800 サンプル（16kHz）。RMVPE の場合は
  5120 サンプルの倍数に切り上げ − 160 した長さにする。
- F0 キャッシュ：過去フレームを保持するリングを持ち、新規分は
  抽出結果の `[3:-1]` を末尾4フレームの位置に書き込む（本家のキャッシュ
  オフセットの意味論を再現する）。
- 特徴の末尾処理：HuBERT 特徴の最終フレームを1つ複製してから ×2 する。
- インデックス検索は `skip_head // 2` フレーム目以降の特徴にのみ適用する。
- 出力接続：本家 GUI の SOLA 相当——クロスフェード長 0.05 秒、
  探索範囲 1 ブロック、入力側の追加文脈（extra）として
  「クロスフェード＋探索＋ブロック」分を先読みする構成。
  再実装では同等の位相合わせクロスフェードを必須とし、パラメータは
  設定可能とする。
- ハイパスフィルタ（4 節）はストリーミングでは filtfilt が使えないため、
  等価な因果フィルタで近似し、差異は 13 節の検証範囲に含める。

## 13. 検証仕様

### 13.1 中間値の一致（決定的な段）

本家実装（PyTorch）を基準実装とし、同一入力に対する次の中間値を比較する。

- HuBERT 特徴：相対誤差が許容範囲内（fp32 実行時・コサイン類似度を併記）
- RMVPE の f0：有声フレーム一致率と、一致フレームの cents 誤差
- coarse（量子化 pitch）：完全一致を目標とし、不一致フレーム率を記録
- 検索ブレンド後の特徴：近傍集合の一致とブレンド結果の相対誤差

### 13.2 合成結果の一致（確率的な段）

- 再実装側の乱数シードを固定し、基準実装側も可能な範囲で固定した上で、
  スペクトル距離（log-spectral distance 等）と F0 軌跡の一致で評価する。
  ビット一致は要求しない。
- 最終判定は聴感：同一の声モデル・同一入力での A/B で「同じ声・同じ言い回しに
  聞こえる」ことを複数モデル（v1/v2、32k/40k/48k、F0 あり/なし）で確認する。

### 13.3 性能

- 基準は現行の外部ランタイム運用時の実測（遅延・RTF）とし、同等以上を目標とする。
- ストリーミング：ブロック処理が実時間内に収まること（RTF < 1、対象は
  CPU / CUDA 相当の実行環境それぞれで計測）。

## 14. ライセンスと再実装の規律

- 本仕様は公開情報（本家の公開リポジトリの挙動・ドキュメント）から処理の
  意味論を記述したもので、実装はこの仕様を根拠に行い、本家コードの
  複写・翻案は行わない。
- RVC 本体は MIT ライセンスであり、法的に移植が禁止されるものではないが、
  本プロジェクトでは保守性・自律性のために再実装の線を採る。
- 重みデータ（3.4）の出所・ライセンスは同梱前に個別確認する。
  特に `hubert_base` は配布元（Hugging Face リポジトリ）ごとに条件が
  異なりうるため、確定した配布元を記録すること。
- 利用者の声モデル（`.pth` / `.index`）は利用者の資産であり、
  アプリは読み取りのみを行う。

## 15. 未決事項

1. `.pth` の読み込み方式：PyTorch チェックポイント形式を直接読む
   （zip 形式の pickle 解釈が必要）か、取り込み時に自前形式へ変換するか。
   互換性と実装量のトレードオフで要決定。
2. 実行基盤：ONNX Runtime を用いる場合、各段のグラフ化範囲
   （HuBERT / RMVPE / 合成器を個別グラフにするか）と、FAISS 検索の置換
   （自前 kNN で十分な規模かどうかは特徴配列の大きさに依存）。
3. 精度：fp16（本家の GPU 既定）と fp32 の使い分け。中間値の許容誤差は
   精度ごとに 13.1 を再定義する。
4. v1 モデルの扱い：流通量が減っている v1（256次元・第9層＋final_proj）を
   初版から必須とするか、v2 優先で後回しにするか。
5. CPU 推論の位置づけ：本家は GPU 前提の構成。CPU のみ環境での
   ストリーミング可否は性能実測のうえ判断する。
6. フォルマントシフト（本家 realtime の `formant_shift`）：初版の対象に
   含めるか。含める場合は F0 と出力リサンプルの双方への適用仕様を別途定める。
