# 音声・TTS専用ページとトップ画面操作 — 設計案

2026-10-29。設計レビュー用。製品コードへの適用はまだ行っていない。

## 決定済みの要望

- ユーザーはTTS欄と既存設定画面の外観の不一致、ボタンと入力欄の見分けにくさを指摘した。
- TTSを詳細設定から独立したページへ移し、トップ画面でもON/OFFできるようにする。
- トップのスイッチは、チャット入力とマイク翻訳の**読み上げだけ**をまとめて切り替える。
  原音・直接VC・ASR・翻訳・OSCの設定を変更しない。
- シード値とInstructionを指定できるようにする。
- 既存VRCTのレイアウトを尊重し、TTS以外の配置や操作を変えない。
- 今回の成果物は原典調査、設計案、実装計画、操作できるモックアップ。

ページ名「音声・TTS」、項目の配置、起動時のTTS OFF、各入力の保存方式は以下の提案。
ユーザーがこれら細部まで承認したとは扱わない。

## 比較した案

| 案 | 利点 | 残る課題・判断 |
|---|---|---|
| A: 詳細設定内でCSSだけ統一 | 最小の変更 | 日常機能を見つけにくく、トップから操作できない |
| B: 詳細設定内で共通行＋折りたたみ | 長い画面を整理し、保存を見つけやすくする | 当初の推奨。ユーザーが専用ページを希望したため配置案を更新 |
| C: 専用ページ＋トップのTTSスイッチ | 設定と普段の操作の入口が明確 | ユーザーの希望に対応する採用案。独立したTTS制御の追加が必要 |

外観はBの共通行・ボタン区別をCに引き継ぐ。左メニューには「音声・TTS」を追加し、
詳細設定にはOSC/WebSocket/OBSなどを残す。ASRの録音操作は文字起こしページに残す。
直接VCは専用ページ内の独立した折りたたみ項目とし、TTSのON/OFF配下にはしない。

## レイアウト・見た目

- メイン画面は既存MainPage/SidebarSection/MainSectionを土台にする。左の既存スイッチの順序、
  言語プリセット・言語交換・翻訳エンジン選択、右上のクイック設定、会話ログと入力欄の配置を維持する。
  ログと入力欄のリサイズ比率、送信ボタンの表示設定、UI拡大率、compact modeも維持する。
- モックの非TTS領域は説明用の概略。モックのロゴ・ログ書式・入力欄・送信ボタンで既存部品を置換しない。
  モックHTML/CSSの移植ではなく、既存React部品への追加として実装する。
- 既存のCSS変数、SectionLabelComponent、Templatesの行構造を使用する。
  入力の即時保存を伴う部品は外観だけを理由に流用せず、現在のdraft→保存APIを維持する。
- 入力欄は暗い面＋控えめな枠、操作ボタンは面のある短いボタン＋動詞ラベル。
  保存は既存のteal系を使い、「読み上げ設定を保存」「エンジン設定を保存」と対象を明示する。
  同じ表示範囲で複数の保存が必要なときは、編集中のformの操作だけを強調する。
- 主要行はチャット入力の読み上げ、必要時の翻訳先、出力方法、出力デバイス、日本語エンジン。
  「仮想ケーブル再生デバイス」は「出力デバイス」に変更し、イヤホンにも出せることを説明する。
- 声の生成設定にseed/Instructionをまとめる。多言語側にも別の設定値を持たせる。
  マイク翻訳、任意の声ファイル、直接VC等は折りたたむ。
- エンジンの未設定・停止・失敗は、折りたたんでいても要約に残す。
  初回未設定または起動失敗では該当する詳細を開く。必須の準備を隠さない。
- 未保存状態は色だけでなく文で示す。保存中・保存成功・失敗も表示する。
  保存中は対象formを固定し、失敗時は編集内容を保持する。
- 行は狭い幅ではラベルの下に操作部を置く。保存欄はそのform内だけでstickyにし、
  フォーカスした入力やStopを覆わないことを確認する。
- 操作対象は通常36px以上の高さを目標とし、24 CSS px最小または間隔の基準を確認する。
  これはデスクトップ向け提案で、デジタル庁の44px推奨を満たしたと主張しない。
  主要文字4.5:1、操作・focus3:1を計測し、既存色の選択を調整する。

## トップ画面のTTSスイッチ

既存MainFunctionSwitchの並び順を変えず、末尾にTTSを追加する。
TTS状態、停止、専用設定への入口はその行の近くへ小さくまとめる。
前案の会話欄上部の大きなTTS帯は採用せず、会話ログや入力欄の領域を新たに削らない。
出力先や詳細な待ち状態は専用設定、またはTTS行の補足表示から確認できるようにする。
簡易表示でもaccessible nameとON/OFF表示を残す。

| 操作・状態 | 契約 |
|---|---|
| TTS OFF | 新規TTSを受け付けず、再生中のTTSと待ち行列をキャンセル。原音/VC/ASR/翻訳/OSCの開始・停止は呼ばない |
| TTS ON | 保存済みのchat/mic読み上げモードで、新しく確定した文章から受け付ける。OFF前の遅い翻訳や待ち音声を再生しない |
| 停止ボタン | 現在のTTSとキューだけを停止。TTS ONの選択は保持し、次の文章は読める |
| 未設定・サーバー停止 | ONに見せず、理由と専用設定へのリンクを表示。モデル取得・ロード・マイク録音は自動開始しない |
| 切替中 | backendの確定を待ち、現在の確定値と「切替確認中」を示す。楽観的に成功扱いしない |
| OFF受理後に再生終了待ち | 「停止中」を表示。受付停止と音声排出完了を同一視しない |
| 接続喪失・エラー | 状態未確認/停止理由を明示し、自動でONに戻さない |
| アプリ再起動 | TTS OFFを提案。保存した読み上げモード/seed/Instructionは保持、モデルは従来どおり停止 |

既存のルートミュートとは独立した`tts_enabled`が必要。受け付け条件は
`tts_enabled && !route_muted && source_mode_enabled`。ルート監視によるミュート解除で
TTS OFFが上書きされない。TTS ONでもルートの安全ミュートは解除しない。
管理経路がミュート中なら「TTS ON・音声経路はミュート中」と表示し、その経路操作へ案内する。
直接音声の原音抑制ポリシーも勝手に解除しない。

## シード値とInstruction

固定speech.cpp0.9.0（49f022a48bc1c7e797aa64dd08d2d9655baf299e）の仕様を基準とする。

- シード: ランダム（既存互換の初期値）／値を指定。ランダムはJSONのseedを省略し、固定は整数を送る。
  0は有効。起動中Irodoriの宣言範囲は0〜9007199254740991（JS安全整数上限）。
  負数・小数・指数表記・範囲外・boolを拒否。文字列として保存/編集し、検証後に数値へ変換する。
- Instruction: `instructions`としてPOST本文に独立して渡す。読み上げ本文への連結や翻訳対象への混入はしない。
  空欄は送らない。UI上限は4000文字を提案し、モデル固有のトークン上限とは区別する。
  改行を許可し、NUL等の不要な制御文字は拒否。サーバーの拒否は切り捨てず理由を表示する。
- 日本語用と多言語用にそれぞれ保存する。選択した出力言語に対応する同じ設定スナップショットから
  voice/seed/instructionsを取り出し、chatとmic翻訳の両経路で同じ規則を使う。
- `/v1/models`の`speech.options`で対応を確認する。モデル・URL・サーバー世代が変わったら再取得し、
  古い応答を捨てる。取得不明と非対応を区別する。
- Irodoriではcaption encoderを持つモデルがinstructions対応。実機のMFモデルは宣言済み。
  Qwen3-TTS0.6Bは非対応。モデル名だけから一律に「Qwen対応」と判断しない。
- 未対応モデルへの非空Instructionは黙って捨てず、保存値を保持して警告し、適用を拒否する。
  基本TTSを使うにはInstructionを空にする。未指定なら従来の最小POSTを維持する。
- 上流は同一リクエスト・同一シード・同一デバイスでの再現を説明しているが、ここではPCM一致試験を
  まだ実施していない。異なるモデル/設定/CPU・GPU間の完全一致や声質固定は保証しない。
  Instructionによる品質・遅延の変化も未測定。

## 自動検証と実機確認

実装計画の各タスクでbehavior testを先に追加する。外観のCSS値を写しただけのテストは作らない。
必要な確認はページ遷移/検索、未保存とsave ack、モデル世代と対応判定、ON/OFF競合、
late finalの破棄、TTS OFF中も原音・VC・OSCが続くこと、seed/instructionsの正確なPOST。

AppImageで通常起動と保存復元、870×654と拡大表示、キーボード、focus、CPU起動失敗案内を確認する。
実モデルは既存の同意済みIrodoriのみを使い、音声は私有経路で検証する。
seed再現は同一デバイスで短文n>=2のPCM比較として別記し、E2E遅延とは混同しない。
Windowsの実機検証は別PCで後日。今回のHTMLの動作確認は製品統合試験ではない。
