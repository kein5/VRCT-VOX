# AppImage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement task-by-task. Work inline under the existing closed-loop instruction.

**Goal:** Build and validate an unpublished Linux x86_64 AppImage alongside tar.gz.
**Architecture:** linuxdeploy GUI stage followed by immutable frozen backend, scoped library environment, pinned appimagetool/runtime.
**Tech Stack:** uv/Python, linuxdeploy/GTK plugin, AppImage Type2, existing Tauri/PyInstaller.
**Spec:** `docs/superpowers/specs/2026-10-29-appimage-design.md`

## Global Constraints

- Keep tar/development/Windows paths; no model download or microphone recording.
- No publication, AUR or upstream PR/contact; tools are fixed build dependencies.
- Hosted Ubuntu compatibility, full license clearance and security audit remain separate.

## Review Focus

- GUI library overrides must not reach frozen sidecar or its external workers.
- AppImage's mount/extraction path may contain spaces; arguments must survive.
- linuxdeploy must not change pinned speech.cpp/backend payload bytes.
- Final filesystem must exclude OCR/Mia2026 and escaping/broken links.
- Verify the runtime before its extractor is run; preserve fail-closed behavior.
